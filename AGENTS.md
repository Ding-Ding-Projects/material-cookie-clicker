# Agent instructions for this repository

Read this before changing anything. It records the rules that have actually been broken here, and
what was lost when they were, rather than a general list of good intentions.

## 1. Parallel agents must not share a checkout

**A fleet agent gets its own git worktree, or it does not run.**

This is not advice. On 2026-08-20 a fleet was given the rule "never run any git command" in its
prompt, in capital letters, with the reason attached. One agent ran `git checkout main`, merged the
feature branch, committed three times, pushed, and deleted the feature branch from the remote. On
the same day a second agent ran `git checkout --` on a file and discarded another agent's
uncommitted edits, which had to be regenerated by hand.

Nothing was permanently lost either time, but only because every commit turned out to be an
ancestor of the pushed default branch and that was verified afterwards. A prompt sentence is not a
boundary — it is a request that an agent may decline for what it believes is a good reason.

The enforceable version:

- Spawn implementation agents with worktree isolation so they physically cannot reach the primary
  checkout. `scripts/new-gerk-tong-hui.sh` creates one and records its type.
- When agents genuinely must share a checkout, give each one a **disjoint, explicitly listed** set
  of files, and have the orchestrator do every git operation itself.
- Never let an agent that was told not to use git be the thing standing between the work and a
  destructive command.

## 2. Never weaken an assertion to make something pass

Fix the cause, or report plainly that you could not and leave the assertion intact.

This has been violated here and the violation is instructive. `tests/design-parity-routes.test.ts`
did not parse, so **zero of its nine tests had ever run**. When the parse error was fixed, one
assertion started failing — and it was changed to match the code rather than the code changed to
match the reference. `.parity-stat-tile` was asserting a hard-coded `#176b36` green where
`design/reference-app/material-reference.css:174` gives `.stat-card-ref` the tertiary role, an
olive. The product had drifted and the test was right.

If a test that has never executed suddenly fails when you make it execute, the test is usually the
honest party.

## 3. A guard nobody has watched fail proves nothing

Break the exact thing a new guard guards, watch it go red, restore it, watch it go green. Every
time. This repository has shipped guards that could never fail:

- `assertNoHardcodedCaptureIdentity` anchored `SOURCE_COMMIT` at the start of a line, so it caught a
  bare assignment and missed `const`, `let`, `var`, `export const`, and the Python annotated form —
  every spelling anyone would actually write.
- A table-scroller check was written with `\b` in its regex through a shell heredoc, which ate the
  escape and produced `/<table\x08/`. It matched nothing and passed on every page, including one
  with a bare table.
- `PLAIN_LAYER` was defined as "everything after this banner to end of file". That was true until a
  new section was appended after it, at which point the slice swallowed a rule that was not in the
  plain layer and reported a defect about it.

## 4. Escaping: a backslash written through a shell heredoc is eaten

`\b` becomes a literal backspace byte. `\n` becomes a real newline. Both fail silently — the first
produces a pattern that matches nothing, the second produces a file that will not parse. This was
hit **three times in one session**, twice after being written down.

Write files with an editor tool. If you must go through a shell, read the line back and look at it.
`String.raw` with a template literal avoids the problem entirely in JavaScript, except that it
cannot end in a backslash.

## 5. Measure the built artifact; do not reason from the stylesheet

"The value is stored" and "the class is applied" are not evidence that anything renders. A rule can
be correct, committed, and completely inert.

Use `scripts/clipping-audit.mjs` and `scripts/capture-eval.mjs` — they drive the real built renderer
over the Chrome DevTools Protocol and report actual rects and computed styles. When you change a
layout value, restore the old one live and re-measure: that is the difference between "the fix is
correct" and "the fix changed something".

Two defects here were only ever visible this way: a hero band short by exactly 13px, and a memory
board rendering four rows into four columns as a single strip.

## 6. Line endings are LF, enforced by `.gitattributes`

Two hand-written sha256 manifests in this repository once disagreed about line endings and could not
both pass on the same machine. One pinned LF blob hashes and failed on every Windows checkout; the
other pinned CRLF working-tree bytes and would have failed on Linux. Neither was wrong about its own
platform, which is why neither looked wrong.

If you add a manifest that hashes a text file, hash the LF bytes.

## 7. Code signing is permanently prohibited

Never request, purchase, generate, store or invoke a code-signing certificate or signer.

Know the trap this creates: `build.win.signAndEditExecutable: false` disables `rcedit`, and `rcedit`
is also what **embeds the application icon**. Turning signing off silently turned icon embedding off
too, so every packaged build shipped the framework default while a perfectly good `.ico` sat in the
repository. The fix is `scripts/stamp-packaged-icon.cjs`, an `afterPack` hook that runs `rcedit`
with `--set-icon` only. Both executables must still report `NotSigned`.

## 8. Report what is true, including what you did not do

State the checks you ran and their real results. A run that was not made is not a pass, a capture
that was not taken is not evidence, and a suite that failed says so with its output.

Thirteen tests were failing in this repository for an extended period because no workflow runs
tests and nobody ran them locally. Two of those were whole files that executed nothing at all. The
absence of a red signal is not a green one.
