# Release icon integrity

The shipped application mark has one committed SVG master and one deterministic generator. This
contract covers the installed application and Squirrel.Windows package identity; a user-selected
appearance logo never changes the executable, installer identity, data directory, update feed, or
release assets.

## Canonical sources and outputs

| Role | Path | Contract |
| --- | --- | --- |
| Master artwork | `assets/material-cookie-clicker-logo-master.svg` | Accessible 512×512 local SVG with bounded seven-chip geometry and no scripts, embedded documents, external references, doctypes, or entities |
| Generator | `scripts/generate-app-icon.mjs` | Recreates the ICO and social preview deterministically |
| Installed icon | `assets/material-cookie-clicker.ico` | Exact generated bytes with 16, 32, 48, and 256px BGRA frames |
| Squirrel URL | `package.json` → `build.squirrelWindows.iconUrl` | Full immutable commit URL whose ICO bytes equal the generated local ICO |

`npm run brand:check` first regenerates both derivatives in memory and compares their bytes with the
committed files. It then runs `scripts/verify-brand-release-integrity.mjs`, which produces the
`material-cookie-clicker.brand-release.v1` proof.

## Immutable current-icon strategy

Squirrel requires an HTTPS icon URL, while a commit cannot contain a URL naming its own not-yet-known
commit SHA. Icon changes therefore use two commits:

1. Commit the master and exact generated derivatives.
2. In a descendant commit, set `build.squirrelWindows.iconUrl` to the first commit's full SHA.

The verifier parses only this exact URL shape:

```text
https://raw.githubusercontent.com/Ding-Ding-Projects/material-cookie-clicker/<40-lowercase-hex>/assets/material-cookie-clicker.ico
```

It rejects mutable refs, redirects, credentials, ports, query strings, fragments, another host, or
another path. When the pinned commit exists locally, the verifier resolves its Git blob, requires
that commit to be an ancestor of `HEAD`, and compares the blob with the current generated ICO. In a
shallow checkout, it fetches only the exact allowlisted immutable URL with redirects disabled and a
15-second deadline, then compares the complete response bytes. If neither proof route is available,
the check fails closed.

## Exact multi-resolution ICO proof

The ICO check accepts exactly four directory entries in this order: 16, 32, 48, and 256px. Each
entry must be square, unique, contiguous, one-plane, 32-bit, uncompressed `DIB-BGRA32`, and must have
the exact DIB, XOR-pixel, and zeroed AND-mask byte counts. Directory and decoded dimensions must
agree, offsets may not overlap or leave gaps, and the container may not contain trailing bytes.

Every frame is decoded bottom-up into canonical RGBA pixels. The proof records the frame and pixel
SHA-256 values, alpha range, and non-transparent pixel count. A frame must contain transparent and
opaque pixels plus at least three visible colours. Finally, the whole ICO must equal the bytes
generated from the SVG master, so a structurally valid but different icon still fails.

`build.icon` and `build.win.icon` must both name the same verified ICO.

## Setup.exe and packaged-application proof

`scripts/packaged-icon-proof.schema.json` is the strict machine-readable
`material-cookie-clicker.packaged-icon-proof.v1` schema. The validator is
`scripts/verify-packaged-icon-proof.mjs`:

```powershell
node scripts/verify-packaged-icon-proof.mjs `
  --manifest release/local-installer-manifest.json `
  --proof-root release/icon-proof `
  --setup-executable release/MaterialCookieClicker-Setup.exe `
  --application-executable "release/win-unpacked/Material Cookie Clicker.exe" `
  --output release/packaged-icon-proof.json
```

The input manifest may use the existing local-installer v2 or workflow-installer v1 schema. It must
contain exactly four extraction records: Setup.exe at 16 and 32px, then the packaged application at
16 and 32px. The validator requires real non-empty PE files, checks each extraction filename, byte
count and file digest, independently decodes each PNG including filters and CRCs, and compares the
canonical RGBA pixels with the matching source-ICO frame.

The normalized proof binds the exact source commit, current source-ICO digest and four source-frame
pixel digests, both executable names/sizes/digests, both extraction sizes for each executable, and a
UTC verification timestamp. Unknown or extra normalized fields are rejected; Setup and application
records cannot substitute for one another.

## Failure modes

- A changed master with stale derivatives fails the generated-byte comparison.
- A syntactically immutable URL serving old bytes fails the Git-blob or HTTPS comparison.
- A shallow offline checkout fails if it cannot independently read the pinned bytes.
- A missing, duplicate, malformed, blank, differently sized, or noncanonical ICO frame fails.
- A missing executable, non-PE file, stale extraction digest, invalid PNG, or changed extracted pixel fails.
- A manifest whose source commit differs from the expected checked-out commit fails.

No failure falls back to a framework icon or filename-only claim.

## Negative red-to-green proof

The focused test deliberately exercises three source-contract failures and four packaged-proof
failures, then restores valid inputs and requires green results. The source verifier also exposes
deliberate CLI mutations so the check itself can be watched fail without editing tracked files:

```powershell
node scripts/verify-brand-release-integrity.mjs --network local --mutate stale-url
node scripts/verify-brand-release-integrity.mjs --network local --mutate generated-byte
node scripts/verify-brand-release-integrity.mjs --network local --mutate missing-frame
npm run brand:check
npx vitest run tests/brand-release-integrity.test.ts
```

The first three commands must exit non-zero. The final two must pass. The test also removes Setup
records, corrupts a declared digest, removes the source-commit binding, and changes extracted pixels
while keeping their file digest internally consistent; every mutation must be rejected before the
valid fixture is accepted again.

## Security and privacy

Master, ICO, executable, and proof inspection is read-only. The default route is local Git and local
bytes. The bounded HTTPS fallback is restricted to the exact immutable public raw URL and sends no
credentials. Proofs contain digests and public artifact names, never signing material, secrets,
private user data, or user-selected logo bytes.

## Verification

```powershell
npm run brand:check
npm run brand:proof
node scripts/verify-brand-release-integrity.mjs --network https
npx vitest run tests/brand-release-integrity.test.ts
```

The packaged validator is exercised with deterministic PE-shaped fixtures and exact PNGs derived
from the committed ICO. A real release candidate supplies the actual Setup.exe, packaged executable,
and extracted icon directory to the same validator.
