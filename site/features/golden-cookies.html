Golden-cookie events

A seeded, replayable random-event schedule: frenzy, click frenzy and windfall.

Current state

Shipped engine, uncaptured surface the scheduler ships with the game surface (src/shared/game/golden-cookie.ts), but no spawned golden cookie has been photographed.

What it does

Every so often a golden cookie spawns as a temporary overlay on the main cookie surface. Click it before its window closes and you get one of three effects:

Default event configuration
EffectWhat it doesDefault
FrenzyMultiplies all production7× for 77 seconds
Click frenzyMultiplies click value3× for 13 seconds
WindfallInstant cookie payout15 minutes of current CPS

By default a golden cookie becomes eligible somewhere between 5 and 15 minutes after the last one, and stays clickable for 15 seconds before despawning unclicked.

Seeded, not random

The spawn schedule uses a small deterministic PRNG (splitmix32) with an explicit stream position that is saved and restored with the game. Math.random() is never called anywhere in this module. Given the same seed and stream index, the same sequence of spawns and effects replays exactly — which is what makes an event system unit-testable at all, and what stops a save/load cycle from re-rolling your luck.

How it is configured

Minimum and maximum delay, the clickable window, both multipliers, both durations and the windfall payout are all fields of one configuration object with a documented default set, not constants buried in the scheduler. The golden treatment uses the tertiary colour role exclusively, so the accent keeps meaning something and is never reused for ordinary chrome.

In the shipped build

The scheduler ships inside the running game, but with a five-to-fifteen-minute spawn window nobody has photographed a spawned golden cookie yet, so the overlay is the one gameplay surface on this site with no capture behind it. Treat the visual description above as the specification it is.
