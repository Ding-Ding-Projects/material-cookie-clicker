Minigame events and Lucky Drawer

The installed desktop application mounts five board controls in its Minigames panel after 100,000 lifetime baked cookies. This documentation page explains that surface; it does not host, emulate, or embed playable minigames.

The surface that is actually mounted

src/renderer/App.tsx imports src/renderer/screens/MinigamesScreen.tsx as PlayableMinigamesScreen and mounts it in the anchored minigames panel. A separate MinigameEventsScreen adapter exists in source but is not the rendered route described here.

The console button and the panel both use the permanent 100,000-lifetime-cookie unlock. The seeded schedule chooses an opportunity 6–12 minutes ahead. Its 30-second clock is the incoming notice window before the scheduled start, not a 30-second round limit. With no active board, the panel also offers a Start button for every board.

Five mounted boards

  • Klondike Solitaire · draw 3: displays the seven-column deal, face-up state, stock, and waste; its mounted buttons draw/recycle and attempt a waste-to-foundation move. Tableau moves are not wired on this screen.
  • Memory Match: reveals the sixteen persisted cards, records pairs, and counts attempts.
  • Cookie 2048: provides four direction buttons, merges a changed board, places the next tile in the first empty cell, and records score, best tile, moves, and win state.
  • Minesweeper: displays an 8×8 board with ten mines; click reveals one cell and right-click toggles a flag. The richer shared flood/chord/first-click helpers are not wired to this mounted screen.
  • Breakout: advances one ball step per press and moves the paddle left or right while persisting the ball vector, bricks, score, lives, and paddle.

Lifecycle and save behavior

Start, Minimize, Resume, Restart, Abandon, and Complete dispatch the persisted lifecycle. Only one board can remain active or minimized. Complete records the board, passes grade 3, awards Golden Tokens, and schedules the next opportunity; Abandon records the board without a completion result.

The active board, schedule, Golden Token ledger, Lucky Chance state, and reward ids live in one optional compatibility block inside the ordinary save JSON. Older saves with no block load empty minigame state instead of invented progress.

With five board ids, the first reachable rare-chain award is the third distinct completed board. Offline time dispatches none of these source actions.

Lucky Chance results

Each draw costs one Golden Token. Its five seeded slots add 10,000 cookies, add 100,000 cookies, start a ×2 production effect for 15 minutes, add one whack_pass raid consumable, or record the rare_cosmetic reward id. Unclaimed ids are selected before repeats; after all five have been claimed, a duplicate result can spend a token. With no token, the reducer leaves the existing state unchanged.

Checks and evidence boundary

The scoped local checks are node scripts/check-site.mjs plus focused runs of tests/completeness-inventory.test.ts, tests/game/disclosure.test.ts, and tests/build-evidence.test.ts. They cover the documentation/site inventory and links, the 100,000-cookie disclosure, and the capture-inventory contract. They do not exercise all mounted board interactions.

Six release-capture rows remain pending: the overall panel plus Klondike, Memory Match, Cookie 2048, Minesweeper, and Breakout. The design-parity promotion inventory has no minigame receipt. Until a later approved built-artifact run supplies those records, this page claims source mounting and scoped local checks only—not a real current screenshot, packaged interaction, or promoted reference/product comparison.
