The defining idea

Material Cookie Clicker's own application features are the game's tech tree. The command palette, the regex builder, the authenticator, the file converter, the local model manager, the appearance editor, the notification centre, local history, scheduled settings, the narrator, exports and bulk actions all appear in-game as tools you discover and buy with cookies, each granting a gameplay bonus. Twenty tools are defined today.

The one rule that must never erode

Unlocking or buying a tool buys a gameplay bonus and its in-game surfacing. It never buys, unlocks, or gates the actual application feature. A player who never touches the tech tree still has the entire regex builder, from settings and from the command palette, at all times.

This is enforced structurally rather than by good intentions. Every tool definition carries a gatesApplicationFeature field that is a literal false with its reasoning recorded beside it; the module deliberately exports no predicate shaped like “is this feature available yet”, and that absence is the design rather than an oversight; and the test suite asserts both. If you are ever tempted to add a convenience helper answering “can the user use X yet”, that is this contract being eroded.

What a tool is made of

Each tool has an English and a Cantonese name, a joke in both languages, one unlock condition and one gameplay effect. Unlock conditions are lifetime cookies, total clicks, an owned count of a named generator, a prestige count, a named achievement, or always. Effects are a click multiplier, a global CPS multiplier, a multiplier on one generator, a discount on a buy-max purchase, an extension to the offline-progress cap, or a bonus to the offline CPS fraction.

The condition discovers the tool; it does not switch the bonus on. Meeting it turns a “??? Tool” card into a named, priced one and posts a Tool discovered notice — and that is all that happens. The bonus applies only once you buy the tool with cookies, like everything else in this game. Nothing here unlocks itself while you watch.

For example, the Command Palette tool is discovered at 50 total clicks and grants +5% click power once bought; the Regex Builder tool is discovered at 10 Cursors and makes Cursors 10% better once bought; Tab Groups does the same for Grandmas.

How it is configured

A player-facing switch, toolProgressionEnabled, decides whether the tree runs normally — discover, then buy (the default) — or whether the whole tree is previewed as unlocked with every bonus counting. It grants nothing and owns nothing: switch it back and every unbought tool is inert again. It changes the game display and the bonus. It never changes whether a feature is reachable — the same contract, restated as a setting.

design/tool-card.html gives every state, including undiscovered, a persistent “Open it now” callout in its own recessed bezel with a solid spark-ring border and an “always available” badge, deliberately unlike the dashed lock chrome around it — precisely because a chunky padlock could otherwise make the escape hatch read as part of the lock. design/tools-tree.html groups nodes into three jewel tiers, bronze through emerald to amethyst.

In the shipped build

The Tools tab is in this release, with the unlocked count, the progress bar and the tool-progression toggle — and it states the no-gating contract on the surface itself, in both languages, twice. What is still true is that several of the underlying application features are logic modules rather than surfaces you can open, so “the feature has always been available” is a contract the game keeps and the application is still growing into.
